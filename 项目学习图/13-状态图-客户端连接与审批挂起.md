# 13 状态图 · 客户端连接与审批挂起

**回答的问题**：GUI 的连接状态机长什么样、断了之后凭什么能自己接上；以及一次审批从"发起"到"有人答复"的等待链。

## 图 A：Electron 主进程的连接状态机

```mermaid
stateDiagram-v2
    direction LR
    [*] --> connecting : RpcTransport.start
    connecting --> connected : TCP 连上（+ auth.hello 成功）
    connecting --> connecting : dial 失败，第 1 次触发 ensureDaemon
    connecting --> reconnecting : 重试中（attempt > 1）
    connected --> reconnecting : socket close / RST（非主动关闭）
    reconnecting --> connected : 退避后 dial 成功
    reconnecting --> error : attempt > 120
    error --> [*] : 提示手动 uv run iwan-core
    connected --> [*] : app quit 主动 stop

    note right of connecting
        渲染层只看到 status 事件 + getStatus 补查
        首次失败即懒启动 daemon（冷启动几十秒）
    end note

    note right of reconnecting
        退避 1s 起、翻倍、封顶 10s
        pending 请求全部 reject("connection lost")
    end note
```

## 图 B：一次权限请求的挂起-唤醒

```mermaid
stateDiagram-v2
    direction TB
    [*] --> evaluating : invoke_tool 调 check_and_wait
    evaluating --> allowed : 规则 allow / trust allow / bypass
    evaluating --> denied : deny 地板 / hook deny / trust deny / plan 模式
    evaluating --> asking : 结论 ASK（default-ask 兜底）
    asking --> pending : create_future + _pending[tool_use_id]
    pending --> allowed : permission.respond allow_once / always_allow
    pending --> denied : permission.respond deny_once / always_deny
    pending --> denied : wait_for 超时（decision=timeout）
    pending --> denied : cancel_session（会话取消）
    allowed --> [*] : 工具执行
    denied --> [*] : 工具结果 permission_denied 回喂模型

    note right of asking
        同时发布 permission.requested 事件
        客户端渲染审批卡（GUI）/ PermissionSelect（TUI）
    end note

    note right of pending
        一 tool_use 一 Future，无 per-session 队列
        会话串行由 SessionManager 的锁保证
    end note
```

## 读图要点

1. **连接状态是"客户端自己的"，不是 daemon 的**：daemon 只知道连接、不知道"重连中"。所以重连后必须重发 `event.subscribe`，否则会处于"连上了但听不见"的假活状态。
2. **`connecting → error` 的阈值是 120 次尝试**（约 2 分钟），配合首次失败即 `ensureDaemon()`——这就是"双击 `iwan work` 什么都不用管"的实现（`daemon.ts` + `rpc-transport.ts:66-90`）。
3. **审批用 Future 而不是轮询**：`check_and_wait` 里 `create_future` 然后 `await wait_for(future, timeout)`；`permission.respond` RPC 只是 `future.set_result(...)`。所以"答复"能在任意一条连接上到达（GUI、TUI 任一客户端都行）。
4. **审批结果会写回策略**：`_apply_response` 不仅唤醒 Future，还把 `always_allow/always_deny` 写进会话缓存 + 持久缓存 + `policy.toml`（`permissions/manager.py:682-760`）——"以后都别问"是落盘的。
